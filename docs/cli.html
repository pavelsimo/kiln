Overview

The kiln binary does two jobs. It installs kiln into a repo, and it answers questions that have exact answers by reading git and GitHub. No model is involved, so every agent and every person gets the same answer to the same question.

Setup

Put kiln in a repo, keep it current, check it's healthy.

initupdatedoctor

Facts

Read-only questions. Same input, same output, --json everywhere.

statuschecksverdictreadyrelease plan

Guarded writes

The two changes that must follow rules, whatever an agent believes.

movemerge

Global flags

FlagWhat it does
--jsonPrint machine-readable JSON on stdout. Progress and errors still go to stderr.
--no-colorTurn color off. kiln also respects NO_COLOR, and never colors output that isn't a terminal.
-C, --dir <path>Run as if kiln was started in that directory.
-v, --verbosePrint every git and gh command kiln runs, to stderr.
-h, --helpHelp for any command, with examples.
--versionPrint the version.

Exit codes

Every command uses the same four codes, so scripts and skills can branch on them.

CodeMeaning
0It worked, or the answer is yes.
1Something failed: git or gh returned an error, a file couldn't be read, you're not in a repo.
2The command was called wrong: an unknown flag, a missing argument, a state that doesn't exist.
3The answer is no. The PR isn't ready, the verdict is stale, the move isn't legal, the merge was refused, doctor found a problem, or there's nothing to release. The reason is printed.

kiln init setup

kiln init [--agents claude,codex,cursor] [--no-github] [--force] [--dry-run]

Installs kiln into the repo you're in. It checks for a GitHub remote and a logged-in gh, then writes .kiln/ (skills, config.yaml, kiln.lock, the memory and verify skeletons), links each skill into your agents' skills folders, adds a marked pointer block to AGENTS.md and CLAUDE.md, creates 14 labels, and writes an issue form, a PR template and a starter CI workflow.

It's safe to run again. Existing files stay as they are.

FlagWhat it does
--agents <list>Agents to link, comma separated. Without it, kiln uses the agents in your config, or detects them from .claude/, .agents/, AGENTS.md and .cursor/, or links all three.
--no-githubSkip the gh login check and label creation. Files are still written.
-f, --forceReplace existing skills and GitHub templates. Never touches config.yaml, memory or verify files.
-n, --dry-runShow what would change without writing anything.
terminal
$ kiln init
  ✓ git repo · gh authenticated as you
  ✓ .kiln/ written · 21 skills · config.yaml · kiln.lock (41 created)
  ✓ linked → .claude/skills  .agents/skills  .cursor/skills
  ✓ 14 labels · issue + PR templates · ci.yml
  next: run /kiln-onboard in your agent

With --json you get root, dry_run, agents, skills, labels and an actions list of {kind, path, detail}, where kind is one of create, replace, skip, keep or link.

kiln update setup

kiln update [--dry-run]

Upgrades the installed skills to the ones built into this binary. For each file it compares three things: what's on disk, the hash in kiln.lock, and the new version.

  • You never touched it: it's replaced.
  • You edited it: your file is kept, and the new version is written next to it as <file>.kiln-new for you to merge.
  • Kiln no longer ships it: it's removed if untouched, kept if you edited it.

New skills get linked into your agents, removed ones get unlinked, and the pointer block is refreshed. Your config and memory are never touched.

FlagWhat it does
-n, --dry-runShow what would change without writing anything.
terminal
$ kiln update
  ✓ replace  .kiln/skills/kiln-watch/SKILL.md
  ! you edited .kiln/skills/kiln-commit/SKILL.md · new version in .kiln/skills/kiln-commit/SKILL.md.kiln-new
  2 changes · kiln 0.2.0

kiln doctor setup

kiln doctor [--no-github]

Checks everything kiln depends on: git, the origin remote, gh login, the 14 labels, the config, installed skills against kiln.lock, pending .kiln-new files, agent links (including Windows copies that drifted), the worktree folder, checks.yaml, and the verify driver.

For the driver it counts commits that touched each feature's source files since DRIVER.md or features/ last changed. That's how kiln-retro knows when to run kiln-verifier maintain.

Exits 3 when something fails. Warnings never change the exit code.

FlagWhat it does
--no-githubSkip the checks that call GitHub (login and labels).
terminal
$ kiln doctor
  ✓ config valid · autonomy gated
  ✓ 21 skills · 1 file edited by you (kiln update keeps them)
  ! driver is behind: 7 commits touched feature sources (billing +4, settings +3)
    fix: kiln-retro runs kiln-verifier maintain

JSON: findings (each {name, level, detail, fix} with level ok, warn or fail), driver ({exists, features, behind}, where behind maps a feature to its commit count) and healthy.

kiln checks read-only

kiln checks [--base <ref>] [--labels a,b] [--json]

Lists the standing checks in .kiln/verify/checks.yaml that apply to this branch. A check applies when one of its path globs matches a file in git diff --name-only <base>...HEAD, or one of its labels is on the issue, or it has no conditions at all. kiln-verify proves each one next to the issue's own predicates.

FlagWhat it does
--base <ref>Compare against this ref. Defaults to origin/<default branch>.
--labels <list>Issue labels to match. Defaults to the labels of the issue in the branch name (kiln/42-…).
terminal
$ kiln checks
3 files changed since origin/main · 1 of 4 standing checks apply
tokens-only  blocking  pnpm lint:tokens exits 0
    matched src/features/settings/Theme.tsx, src/theme.css
{

  "changed": ["src/features/settings/Theme.tsx", "src/theme.css", "README.md"],
  "checks": [
    {
      "id": "tokens-only",
      "when": { "paths": ["src/**/*.css", "src/**/*.tsx"] },
      "predicate": "pnpm lint:tokens exits 0",
      "blocking": true,
      "from": "lessons.md · strong · #31 #42 #49",
      "matched": ["src/features/settings/Theme.tsx", "src/theme.css"]
    }
  ]
}

kiln verdict read-only

kiln verdict [<issue>] [--ref <rev>] [--only verify|review] [--accept-inconclusive] [--json]

Reads the latest kiln-verify and kiln-review rows from the task journal and says whether they still hold for the code at HEAD. The issue comes from a kiln/<n>-<slug> branch name when you leave it out.

A recorded result is fresh when it's for the same commit, when the tree is identical apart from .kiln/memory/ (so logging the verdict never makes it stale), or when the change has the same git patch-id as before (a clean rebase onto a newer main).

Exits 3 unless verify is VERIFIED, review is PASS, and both are fresh.

FlagWhat it does
--ref <rev>Judge this commit instead of HEAD. The journal is read from it too.
--only <part>Judge just verify or just review. kiln-verify uses --only verify to confirm its own row before review has run.
--accept-inconclusiveCount an INCONCLUSIVE verify as passing. That's a human decision, made at ◆2.
terminal
$ kiln verdict
#42 · head 9f3b2c1 · .kiln/memory/tasks/42-dark-mode.md
  ✓ verify  VERIFIED on a1c9e0f · same-tree
  ✓ review  PASS on a1c9e0f · same-tree
  fresh

JSON: issue, head, journal, verify and review (each {result, sha, ts, fresh, how}, where how is same-sha, same-tree, patch-id or stale), fresh and reasons.

kiln ready read-only

kiln ready <pr> [--accept-inconclusive] [--json]

Says whether a PR can squash merge right now, and lists everything that's left instead of stopping at the first problem. It checks, in order:

  1. open: the PR is open and not a draft
  2. conflicts: GitHub says it merges cleanly
  3. ci: every check passed and none are still running
  4. review: nobody requested changes, and branch protection isn't waiting on a review
  5. threads: no unresolved review threads
  6. closes: the body says Closes #N
  7. verdict: a fresh VERIFIED and PASS in the task journal at the PR's head

Housekeeping PRs on kiln/ branches without an issue number (kiln/release-v1.4.0, kiln/retro-2026-10-28, kiln/onboard) skip the last two: their gate is CI. Exits 3 when the PR isn't ready.

terminal
$ kiln ready 57

  ✓ conflicts no conflicts with main
  ✗ ci        2 of 6 still running
  ✓ review    no review required
  ✓ threads   all review threads resolved
  ✓ closes    closes #42
  ✓ verdict   VERIFIED on a1c9e0f (same-tree) · review PASS
  not ready

kiln release plan read-only

kiln release plan [--version X.Y.Z] [--pre rc] [--ref <branch>] [--json]

Works out the next version from the gitmoji squash commits since the last tag, and drafts the changelog section. It never writes, tags or publishes anything: the /kiln-release skill does that, after asking you.

CommitBumpChangelog section
💥, or ! after the type, or a BREAKING CHANGE: footermajor (minor before 1.0)Changed, marked BREAKING
✨ featminorAdded
🐛 fix · 🚑️ hotfixpatchFixed
⚡️ perf · ⬆️ deps · ♻️ refactorpatchChanged
🗑️ deprecatepatchDeprecated
🔥 removepatchRemoved
🔒️ securitypatchSecurity
🔧 ✅ 📝 👷 🎨 🔖noneleft out

The highest bump wins. Without any tags, the first release is 0.1.0. Exits 3 when nothing user-visible merged since the last tag (pass --version to release anyway), or when the tag already exists locally or on origin.

FlagWhat it does
--version <X.Y.Z>Use this version instead of the inferred one. It must be newer than the last tag.
--pre <label>Cut a pre-release: --pre rc gives 1.4.0-rc.1, then rc.2, and so on.
--ref <branch>The branch to release. Defaults to origin/<default branch>.
terminal
$ kiln release plan
KILN release · v1.3.0 → v1.4.0
rule   ✨ feat in 2 PRs → minor
since  v1.3.0 · 6 commits · 3 left out

## [1.4.0] - 2026-10-28

### Added

- dark mode in settings (#42)
- export history as CSV (#51)

### Fixed

- login no longer loops after the session expires (#43)

[1.4.0]: https://github.com/acme/app/compare/v1.3.0...v1.4.0

JSON: last_tag, version, tag, bump, rule, ref, commits (each with sha, subject, emoji, type, scope, breaking, pr, description, bump and section), sections, left_out, changelog and compare_url.

kiln move guarded write

kiln move <issue> <state> [--reason "…"] [--dry-run]

Moves an issue to its next kiln:* label, and refuses anything the state machine doesn't allow. Labels are how anyone can see where a task is on GitHub, so they only move one legal step at a time.

FromCan go to
no kiln labelneeds-triage, ready
needs-triageready
readyplanned, in-progress
plannedin-progress, ready
in-progressreview
reviewin-progress (changes requested)
any of themblocked, with --reason
blockedthe state it came from

Blocking posts a comment with your reason and a hidden marker of where the issue came from, so unblocking can only send it back there. An illegal move exits 3 and says what's allowed.

FlagWhat it does
--reason <text>Why the issue is blocked. Required for blocked.
-n, --dry-runCheck the move without changing any labels.
terminal
$ kiln move 42 planned
  ✓ #42 moved kiln:ready → kiln:planned
$ kiln move 42 review
kiln: #42: kiln:planned → kiln:review isn't a legal move (from kiln:planned you can go to kiln:in-progress, kiln:ready, kiln:blocked)

kiln merge guarded write

kiln merge <pr> [--accept-inconclusive] [--no-cleanup] [--dry-run]

Squash merges a PR, but only after running every kiln ready check and getting a yes. An agent that talks itself into merging still hits this wall.

  • The merge is pinned to the head commit kiln just checked, so a late push can't sneak in.
  • It reads the PR back until GitHub reports it MERGED, and records the merge commit.
  • It removes the kiln:* labels from the closed issue.
  • It cleans up: the task's worktree (only if it has no local changes), the local branch, and the remote branch.
FlagWhat it does
--accept-inconclusiveMerge with an INCONCLUSIVE verify. Only a human makes that call, at ◆2.
--no-cleanupKeep the worktree and branches.
-n, --dry-runRun every check, but don't merge.
terminal
$ kiln merge 57
  ✓ #57 squash merged · 4e81d07
  ✓ removed kiln:review from #42
  ✓ worktree ../app.kiln/42-dark-mode removed
  ✓ branch kiln/42-dark-mode deleted
  ✓ remote branch kiln/42-dark-mode deleted

JSON: pr, merged, merge_sha, issue, cleanup and dry_run. When kiln ready says no, nothing is merged, the reasons are printed, and it exits 3.

Files kiln reads

The fact commands read a few plain files in your repo. Skills write them; the binary only reads.

FileRead byWhat kiln looks for
.kiln/config.yamlevery commandautonomy, gates, rigor, worktrees, release tag format
.kiln/memory/tasks/<n>-<slug>.mdverdict, ready, statusfrontmatter and the journal table; the last kiln-verify and kiln-review rows
.kiln/memory/lessons.mdstatuslast_retro in the frontmatter
.kiln/verify/checks.yamlchecks, doctorid, when.paths, when.labels, predicate, blocking
.kiln/verify/features/*.mddoctorthe sources globs behind each feature
.kiln/kiln.lockupdate, doctora sha256 for every installed skill file
