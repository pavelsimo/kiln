Before you start

Kiln lives inside a GitHub repo and works through the tools you already have. Make sure these three are in place:

  • A git repo with a GitHub remote named origin. Issues, labels and pull requests are where kiln keeps its state.
  • The GitHub CLI, logged in. Run gh auth status. If it complains, gh auth login fixes it.
  • A coding agent that reads skills: Claude Code, Codex or Cursor. Kiln links its skills into all three.

step 1Install the binary

Kiln is one small Go binary with every skill baked in. Pick whichever install suits you.

Homebrew

macOS and Linux.

terminal
$ brew install pavelsimo/tap/kiln

Go

Needs Go 1.25 or newer.

terminal
$ go install github.com/pavelsimo/kiln@latest

Download

Grab a build for Linux, macOS or Windows from GitHub Releases and put it on your PATH.

Check that it worked:

terminal
$ kiln version
kiln 0.1.0

step 2Install it into your repo

From anywhere inside your repo, run kiln init. It checks git and gh first, then sets everything up in one go.

terminal
$ kiln init
  ✓ git repo · gh authenticated as you
  ✓ .kiln/ written · 21 skills · config.yaml · kiln.lock (41 created)
  ✓ linked → .claude/skills  .agents/skills  .cursor/skills
  ✓ 14 labels · issue + PR templates · ci.yml
  next: run /kiln-onboard in your agent

Here's what that wrote:

WhereWhat
.kiln/skills/The /kiln router, its six playbooks and twenty kiln-* skills.
.kiln/config.yamlAutonomy, gates, rigor by size, conventions. Sensible defaults; yours to edit.
.kiln/memory/An empty PROJECT.md, lessons.md, and folders for decisions and task journals.
.kiln/verify/Where the app driver and standing checks will live. evidence/ is gitignored.
.kiln/kiln.lockA fingerprint of every skill file, so kiln update can tell your edits from its own.
.claude/skills/ and friendsOne symlink per skill, so every agent reads the same files.
AGENTS.md, CLAUDE.mdA small marked block that points any agent at the router. Everything outside the markers is yours.
GitHubFourteen labels, an issue form, a PR template and a starter ci.yml.

Kiln never overwrites files that already exist. If you have your own ci.yml or PR template, it leaves them alone. Running kiln init twice is harmless.

Handy flags --agents claude,codex links only the agents you name. --dry-run shows what would change. --no-github skips gh and the labels. --force refreshes skills and GitHub templates, but never touches your config, memory or verify files.

Commit the result so your whole team (and every agent) gets it:

terminal
$ git add .kiln .claude .agents .cursor .github AGENTS.md CLAUDE.md
$ git commit -m "🔧 chore: install kiln"
$ git push

step 3Introduce kiln to your project

The binary can't read your code, so the next step happens in your agent. Open Claude Code, Codex or Cursor in the repo and run:

your agent
› /kiln-onboard

The onboard skill reads your manifests and CI to find the real commands, then:

  • writes .kiln/memory/PROJECT.md: your stack, your test, lint, build and e2e commands, your conventions, and the paths kiln should never touch without asking
  • swaps the placeholder step in kiln's starter ci.yml for those real commands
  • seeds .kiln/verify/checks.yaml with standing checks from your CI
  • hands off to kiln-verifier, which learns how to launch and drive your app and proves it with one full run

All of it lands as one PR, 🔧 chore(kiln): onboard <repo>, for you to read and merge.

step 4Check the setup

kiln doctor looks at everything kiln depends on and tells you what to fix. Warnings are fine to live with. It exits with 3 only when something is actually broken.

terminal
$ kiln doctor

  ✓ gh authenticated as you

step 5Your first task

Hand kiln a sentence. The router restates the goal, sizes it, picks a playbook and copies its steps into your agent's todo list.

your agent
› /kiln "add a dark mode toggle to settings"
  goal   Users can switch Settings to a dark theme, and the choice sticks.
  type   feature · size M · playbook feature · autonomy gated
  ✓ #42 opened · 3 predicates · plan posted
  ◆ gate 1 the plan for #42 is waiting for you

Read the plan on the issue. Say yes and kiln builds it in its own worktree, test first, then proves every acceptance criterion on the real app, gets a review, opens the PR and takes it to green. It stops once more before merging:

your agent
  ✓ 3/3 predicates VERIFIED on a1c9e0f
  ✓ review PASS · PR #57 · CI 6/6 green
  ◆ gate 2 merge #57? ▍

Say yes again and kiln merge squash merges it, but only if kiln ready agrees that CI is green, nobody asked for changes, and the verdict still matches the code. Then it cleans up the worktree and branch.

Any time you want the big picture, ask for the factory floor:

terminal
$ kiln status
KILN · acme/app · 2 in flight · 1 waiting on you
#42   ✨ add dark mode to settings   M  glaze  PR #57  ● CI 4/6
#43   🐛 login redirect loop          S  ship   PR #58  ✓ green · ◆2 you
backlog  6 ready · 2 need triage · 1 blocked (#39)

Choose how often it stops

The default, gated, stops at the two gates: before any code is written and before the merge. You can change that in .kiln/config.yaml:

.kiln/config.yaml
# How often kiln stops for you: manual | gated | autopilot
autonomy: gated
gates: [plan, merge]
ModeWhat happens
manualRuns one skill, reports, and waits for you. A good way to start trusting it.
gatedRuns the whole playbook and waits at ◆1 (the plan) and ◆2 (the merge).
autopilotGoes from task to merged PR while kiln ready passes. Size L tasks still stop at the plan.

Some things stop in every mode, no matter what: force-pushing a shared branch, deleting unmerged work, releasing or tagging, merging with failing checks, changing secrets or repo settings, and messaging anyone outside the repo.

Stay current

New versions of kiln ship new versions of the skills. Upgrade the binary, then let it refresh what's installed:

terminal
$ brew upgrade kiln
$ kiln update --dry-run
dry run: nothing was written
  ✓ replace   .kiln/skills/kiln-watch/SKILL.md
  ! you edited .kiln/skills/kiln-commit/SKILL.md · new version in .kiln/skills/kiln-commit/SKILL.md.kiln-new
  2 changes · kiln 0.2.0
$ kiln update

Files you never touched are replaced. Files you edited are kept exactly as they are, and the new version lands next to them as .kiln-new so you can merge the two by hand. kiln doctor reminds you about any .kiln-new files still waiting.
