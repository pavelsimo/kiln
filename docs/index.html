kiln

A software factory you install into your repo.

Hand kiln a task. It opens the issue, plans it, builds it in its own worktree, proves it works, ships the pull request, and writes down what it learned so the next task starts warmer. Plain skills, gh and git, and memory you can read in a diff.

What you get

The features that matter

ISSUE-FIRST

The issue is the unit of work

No code before a GitHub issue with observable acceptance criteria. One issue, one branch, one worktree, one PR that says Closes #N.

kiln:* labels are the state machine. Anyone can see where a task is on GitHub.
ONE DOOR IN

A router and six playbooks

/kiln restates the goal, sizes it, and picks feature, bug, refactor, chore, investigate or release. Each action skill also works on its own.

☒ skip: kiln-plan · chore with no design decision
VERIFICATION

Proven on the real surface

Each criterion is a predicate checked on the running app, the real command, or a value read back. A green build is not proof. Tests are audited before they count.

VERIFIED · NOT VERIFIED · INCONCLUSIVE
“couldn't check” is never a pass
MEMORY

Memory you can read in a diff

Project facts, task journals, decisions and lessons live in .kiln/memory/, committed with the work. One writer per file, so parallel tasks never conflict.

lessons graduate: candidate → recurring → strong → standing check
CODE OR AGENT

Facts in code, judgment in skills

If git or gh can answer it exactly, the kiln binary does, with no model involved. Skills keep the work that needs reading code or making a call.

kiln merge refuses red CI or a stale verdict, whatever the agent believes
FACTORY FLOOR

Several firings at once

Each issue gets its own git worktree beside the repo, so up to three tasks build in parallel. kiln status shows what's in flight and what's waiting on you.

#42 glaze ● CI 4/6 · #43 ship ✓ ◆2 you
RELEASES

Many firings, one tag

kiln-release infers the version from gitmoji squash commits, writes CHANGELOG.md once through a release PR, tags the merge commit, and publishes.

✨ feat → minor · 🐛 fix → patch · 💥 → major
HOUSE STYLE

Conventions built in

Gitmoji plus Conventional Commits, kiln/42-dark-mode branches, ready PRs (never drafts), squash merges, and a PR template with a verification section.

✨ feat: add dark mode to settings (#42)
AGENT-AGNOSTIC

One source, every agent

Skills live in .kiln/skills/ and are symlinked into Claude Code, Codex and Cursor. Edit a skill once and it changes everywhere. Standalone, no runtime dependencies.

kiln update keeps your edits, writes the new version as .kiln-new
Autonomy × rigor

Autonomy is a setting. Safety is not.

One setting decides how often kiln stops for you. The task's size decides how hard it checks its own work.

manual

Runs one skill, reports, suggests the next step. Good while you're building trust.

stops after every step

gated default

Runs the whole playbook and waits only at the two gates.

◆1 plan · ◆2 merge

autopilot

Task to merged PR while kiln ready passes. INCONCLUSIVE never merges on its own.

◆1 for size L · hard stops

Always stops

  • force-push to a shared branch
  • delete unmerged work or data
  • deploy, release, or tag
  • merge with failing checks
S
Self-verify, self-reviewOne area, about 100 lines. Running it is enough.
M
Fresh checker, independent reviewerUI and API changes must be seen in the running app.
L
Verifier swarm, adversarial reviewSplit into sub-issues. The plan always needs a human.
