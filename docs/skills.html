Twenty‑one skills, one router

A skill is a folder with a SKILL.md that your coding agent reads and follows. /kiln is the router that chains them; every other skill is one step of the lifecycle that you can also run by hand. Type the /kiln-* commands inside your agent (Claude Code, Codex, Cursor). Plain kiln … commands run in a terminal.

How skills work

Plain files your agent follows

router

The router chains them

/kiln restates your goal, sizes the task and picks a playbook. It copies the playbook's steps into your todo list, then for each step reads .kiln/skills/<name>/SKILL.md and follows it exactly. That file is the instruction, so a skill behaves the same whoever calls it.

on its own

Every skill also works alone

Type /kiln-issue to write an idea down, /kiln-verify to prove any branch, or /kiln-release to ship. Action skills only run when you or the router call them by name. They never trigger by accident.

one copy

One folder, every agent

Skills live in .kiln/skills/. kiln init symlinks each skill folder into .claude/skills, .agents/skills and .cursor/skills, so Claude Code, Codex and Cursor all read the same files. Your own skills sit beside them untouched.

yours

Your edits survive updates

Skills are Markdown you can change. kiln update replaces a file only when its hash still matches kiln.lock. A file you edited is kept, and the new version lands next to it as SKILL.md.kiln-new for you to merge. kiln doctor lists any you haven't merged yet.

Skills never re-derive facts. They ask the binary (kiln status, checks, verdict, ready, release plan, all with --json), change kiln:* labels only through kiln move, and merge only through kiln merge. See facts in code, judgment in skills.

/kiln "<task>"across

The router and the single entry point. Restates your goal in one sentence, classifies the type and size, picks a playbook, copies its steps into your todo list word for word, and chains the kiln-* skills while respecting autonomy and gates. Give it an issue number (/kiln #42) to work an existing issue, or nothing at all to see what needs attention.

.kiln/config.yaml · PROJECT.md · lessons.md · playbooks/<playbook>.md · kiln status --json
writes
the todo list in your agent · journal rows go through kiln-log
runs

/kiln-issueGather

Turns a rough request into a GitHub issue: a gitmoji title, the problem, acceptance criteria P1..Pn with at least one must not change:, what's out of scope, and type and size labels. Asks up to five questions in one batch when the request is vague. Never invents criteria.

Sweeps issues labeled kiln:needs-triage. Closes duplicates, fills in missing acceptance criteria or asks for them, sets type and size, promotes finished issues, and orders the ready queue by priority. Shows its plan as one table before writing anything.

runs

Builds a read-only map of the code a task will touch: where things live, how they connect, which tests cover them, and the gotchas. Every claim gets a file:line. For size L it splits the area across 2 to 4 parallel read-only subagents.

Posts the plan as an issue comment: approach, files, test plan, risks, and the predicates restated word for word. Splits L work into sub-issues, moves the issue to kiln:planned, and holds gate ◆1. A revision is a new comment, so the history stays visible.

/kiln-startFire

Claims the issue. Checks max_in_flight, creates a worktree and a kiln/<n>-<slug> branch from a freshly fetched default branch, assigns you, moves the issue to kiln:in-progress, and creates the task journal through kiln-log.

reads
kiln status --json · .kiln/config.yaml · PROJECT.md
writes

runs
git fetch origin --prune · git worktree add -b · gh issue edit --add-assignee @me · kiln move <n> in-progress
/kiln-buildFire

Implements the plan test-first inside the worktree, one predicate at a time: red, green, clean, commit. A bug fix commits its failing reproduction before the fix, and a refactor pins behavior with characterization tests first. Finishes with test, lint, typecheck and build all green.

reads
the predicates and plan · PROJECT.md · lessons.md · the task journal
writes
code and tests, committed through kiln-commit · optional decision records
runs
PROJECT.md's test, lint, typecheck and build commands
/kiln-commitFire

Makes atomic commits such as ✨ feat: add theme toggle to settings, staging explicit paths only. Reorders the branch into small logical commits once, before verify, keeping the reproduction before the fix. Never adds Co-authored-by trailers or AI attribution.

reads
git status · git diff · git log origin/<default>..HEAD
writes
commits on kiln/<n>-<slug>
runs
git add <paths> · git commit · git rebase -i --autosquash
/kiln-verifyGlaze

Proves the change on the real surface. Turns the acceptance criteria and matching standing checks into predicates, picks the check that fits each surface, drives the running app through DRIVER.md when needed, and audits every test it cites. Each predicate gets VERIFIED, NOT VERIFIED or INCONCLUSIVE with an evidence-ladder step, tied to a commit SHA. M uses a fresh-context checker, L a three-lane swarm.

reads
the predicates · kiln checks --json · git diff origin/<default>...HEAD · verify/DRIVER.md · verify/features/
writes
report and row through kiln-log · evidence/<issue>/ (gitignored)
runs
kiln checks --json --labels · project gates · driver steps · git worktree add --detach (bugs) · kiln verdict <n> --only verify --json
/kiln-verifier create · maintainGlaze

Builds and maintains the app driver. create learns how to launch, health-check, drive and clean up your app, writes DRIVER.md and 3 to 5 feature files, and proves them with one full run. maintain checks every feature against the source and the live app, fixes only the map, files product gaps as issues, and ships at most one PR.

reads
PROJECT.md · .kiln/config.yaml · run scripts, routes, CLI commands, seeds · kiln doctor
writes
verify/DRIVER.md · verify/features/*.md · issues for product gaps
runs
git log --since=90.days · git ls-files · gh issue create · kiln move <n> needs-triage
/kiln-reviewGlaze

Reviews the branch at a depth set by its size: S a self-review checklist, M a fresh-context reviewer subagent, L three adversarial reviewers whose findings count only when a reproducing command reruns. Returns PASS or FIX for the exact HEAD SHA, and never changes code.

reads
the issue · git diff origin/<default>...HEAD · PROJECT.md · lessons.md · kiln verdict <n> --json
writes
review report · row through kiln-log · on FIX: kiln move <n> in-progress
runs
git rev-parse --short=7 HEAD · git diff · kiln verdict <n> --json
/kiln-prShip

Confirms that verify and review are fresh for HEAD, pushes the branch, and opens a ready PR (never a draft) with a gitmoji title and the template sections, ending in Closes #N. Then moves the issue to kiln:review.

reads
kiln verdict <n> --json · the task journal · pull_request_template.md
writes
pushed branch · one ready PR · kiln:review
runs
git push -u origin · gh pr create · gh pr view · kiln move <n> review
/kiln-watchShip

Takes an open PR to green. Asks kiln ready what's left, then handles conflicts, review threads and CI, in that order. Retries a flaky job once; if CI stays red, it blocks the issue with the reason. Never merges.

reads
kiln ready <pr> --json · kiln verdict <n> --json · review threads · CI logs · lessons.md
writes
fix commits · thread replies · one retry per flaky job
runs
kiln ready <pr> --json · git rebase · gh api graphql · gh run view --log-failed · gh run rerun --failed
/kiln-merge <pr>◆2Ship

Holds gate ◆2. Shows what kiln ready reports, waits for your yes according to autonomy, then merges only through kiln merge and reads back the result and cleanup. An INCONCLUSIVE predicate needs your explicit acceptance in every mode.

reads
kiln ready <pr> --json · .kiln/config.yaml · the verify report · kiln status --json
writes
the squash merge, through kiln merge only
runs
kiln ready <pr> --json · kiln -C <main> merge <pr> --json · gh issue view
/kiln-release [version | --pre rc]◆ releaseShip

Cuts a release of what main already has, outside the task loop. Takes the version from kiln release plan, edits CHANGELOG.md for readers, lands it through a release PR, and stops at the release gate in every mode. Then merges, tags the merge commit and publishes.

reads

writes
CHANGELOG.md · version_files · release PR · annotated tag · GitHub Release
runs
kiln release plan --json · gh pr create · kiln merge <pr> --json · git tag -a · gh release create --verify-tag
/kiln-logTemper

The only writer of task journals. Creates the journal at kiln-start, appends the row every other skill hands over, records the verify report, decisions, skips and retro notes, and commits it. Its final pass runs before ◆2, because kiln merge deletes the branch.

reads
the handed-over row · the journal · the current branch
writes
.kiln/memory/tasks/<n>-<slug>.md, and nothing else
runs
git add <journal> · git commit -m "📝 docs(kiln): log <skill> for #<n>" · git push
/kiln-retroTemper

Reads the journals merged since the last retro and turns recurring friction into lessons with confidence levels. Graduates strong, checkable lessons into standing checks, proposes edits to PROJECT.md and to kiln's own skills, runs kiln-verifier maintain when kiln doctor reports drift, and ships it all as one PR.

kiln status --json · lessons.md · tasks/*.md · checks.yaml · .kiln/skills/*/SKILL.md · kiln doctor
writes
lessons.md · checks.yaml · PROJECT.md · skill edits · one PR on kiln/retro-<date>
runs

Playbooks

Six step lists

The router picks one playbook per task from its type and copies its todo list into your agent word for word, filling in the <placeholders>. A skipped step is never deleted: it is rewritten in place as skip: <skill> · <reason>. The files live in .kiln/skills/kiln/playbooks/. For how each stage runs, see the playbook matrix.

runs in fullruns lightskipped◆ gate

feature

type:feature

New behavior a user can see. Every stage runs in full. Review and verification depth follow the size label.

GatherShapeFireGlazeShipTemper
  1. kiln-recall · lessons, decisions and past tasks about <area>
  2. kiln-issue · <gitmoji> <title> with predicates P1..Pn
  3. kiln-explore · map the code in <area>
  4. ◆1 kiln-plan · plan comment on #<n>
  5. kiln-plan · decision record in the worktree, if the plan made a call
  6. kiln-start · ../<repo>.kiln/<n>-<slug>
  7. kiln-build · test-first, one predicate at a time
  8. kiln-commit · gitmoji commits, reordered before the PR
  9. kiln-verify · P1..Pn + standing checks · checker <self|fresh|swarm>
  10. kiln-review · <self|independent|adversarial>
  11. kiln-pr · ready PR, Closes #<n>
  12. kiln-watch · conflicts, threads, CI
  13. kiln-verify · swarm at the merge-ready head
  14. kiln-log · final pass: skips, retro notes, pushed before ◆2
  15. ◆2 kiln-merge · PR #<pr>
  16. kiln-retro · offer if retro_queue is 5 or more

Never skips kiln-recall. Only an S feature may waive the plan, and only when you ask. The swarm (step 13) runs for size L.

bug

type:bug

Something is wrong today. The failing reproduction lands before the fix, and verification sees the bug on the old build and its absence on the new one.

GatherShapeFireGlazeShipTemper
  1. kiln-recall · past bugs and lessons about <area>
  2. kiln-issue · 🐛 <title> with repro steps and predicates P1..Pn
  3. kiln-explore · light: trace the failing path in <area>
  4. ◆1 kiln-plan · cause, fix and repro test on #<n>
  5. kiln-start · ../<repo>.kiln/<n>-<slug>
  6. kiln-build · failing reproduction test, committed alone
  7. kiln-build · smallest fix that turns the reproduction green
  8. kiln-commit · ✅ test: reproduce … then 🐛 fix: …, in that order
  9. kiln-verify · before/after: 2 of 2 on old, 0 of 2 on new · root cause at file:line
  10. kiln-review · <self|independent|adversarial>
  11. kiln-pr · ready PR, Closes #<n>
  12. kiln-watch · conflicts, threads, CI
  13. kiln-log · final pass: skips, retro notes, pushed before ◆2
  14. ◆2 kiln-merge · PR #<pr>

Never skips the reproduction (step 6) or the before and after check (step 9). An S bug skips the plan: the repro test is the plan.

refactor

type:refactor

Same behavior, better shape. Behavior is pinned by tests before anything moves, and the proof is that observable output did not change.

GatherShapeFireGlazeShipTemper
  1. kiln-recall · decisions and lessons about <area>
  2. kiln-issue · ♻️ <title> naming the target shape, predicates P1..Pn
  3. kiln-explore · map callers and tests of <area>
  4. ◆1 kiln-plan · smallest safe steps on #<n>
  5. kiln-start · ../<repo>.kiln/<n>-<slug>
  6. kiln-plan · decision record for the target shape, in the worktree
  7. kiln-build · characterization tests pin current behavior, green on the old code
  8. kiln-build · refactor in small steps, pinned tests green after each
  9. kiln-commit · ✅ test: pin … first, then ♻️ refactor: … steps
  10. kiln-verify · pinned tests green · output diffed before and after
  11. kiln-review · <self|independent|adversarial>
  12. kiln-pr · ready PR, Closes #<n>
  13. kiln-watch · conflicts, threads, CI
  14. kiln-verify · swarm at the merge-ready head
  15. kiln-log · final pass: skips, decisions, retro notes, pushed before ◆2
  16. ◆2 kiln-merge · PR #<pr>

Never skips kiln-explore or kiln-plan: a refactor that misses a caller breaks it, and the step order is the whole safety story.

chore

type:chore · type:docs

Deps, config, docs, cleanup. There is nothing to design, so the plan is skipped and verification runs light.

GatherShapeFireGlazeShipTemper
  1. kiln-recall · lessons about <area>
  2. kiln-issue · <gitmoji> <title>, short issue
  3. kiln-plan · only if the chore hides a design decision
  4. kiln-start · ../<repo>.kiln/<n>-<slug>
  5. kiln-build · light: make the change
  6. kiln-commit · <gitmoji> chore: <what>
  7. kiln-verify · light: lint · build · matching standing checks
  8. kiln-review · <self|independent>
  9. kiln-pr · ready PR, Closes #<n>
  10. kiln-watch · conflicts, threads, CI
  11. kiln-log · final pass: skips, pushed before ◆2
  12. ◆2 kiln-merge · PR #<pr>

The plan runs for size L or when the chore forces a choice. A chore that turns out to change behavior is re-routed as a feature or bug.

investigate

a question

Answer a question. No code change, no branch, no PR. The output is a written report and, when a finding should outlive the conversation, a decision record.

GatherShapeFireGlazeShipTemper
  1. kiln-recall · past tasks, decisions and lessons about <topic>
  2. kiln-issue · only if the user wants the question tracked
  3. kiln-explore · read-only map of <topic>
  4. report · answer with file:line evidence and a ladder step per claim
  5. skip: kiln-start · kiln-build · kiln-commit · read-only
  6. skip: kiln-verify · nothing to verify
  7. skip: kiln-pr · kiln-watch · kiln-merge · no PR
  8. decision record · decisions/<date>-<slug>.md for findings that outlive this conversation
  9. skip: kiln-log · no task worktree, rows go in the report

Steps 5, 6, 7 and 9 are skipped by definition and stay in the list, so the run shows what didn't happen.

release

shipping

Ship what main already has. A release has no issue of its own: it gathers every task merged since the last tag. The release gate stops in every autonomy mode.

GatherShapeFireGlazeShipTemper
  1. skip: kiln-issue · a release collects closed issues
  2. kiln-release · preflight and kiln release plan --json → v<version>
  3. kiln-release · changelog section and version_files edited for readers
  4. kiln-release · 🔖 chore(release): v<version> on kiln/release-v<version>
  5. kiln-release · ready release PR, CI green through kiln-watch
  6. kiln-log · tasks/release-v<version>.md on the release branch, pushed before the gate
  7. ◆ release gate · version, changelog, CI and publish route shown · always stops
  8. kiln-release · kiln merge, tag the merge SHA, push the tag, publish

Nothing else may be skipped. If kiln release plan exits 3, the playbook stops and reports why.
